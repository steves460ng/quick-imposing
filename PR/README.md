# PR 디렉토리 운영 규칙

이 저장소는 GitHub Pull Request 기능 대신 이 디렉토리의 Markdown 문서로 변경을 제안하고 검토한다(2026-11-11부터). 구현 에이전트(Codex)의 PR 기능을 쓸 수 없게 된 상황에 맞춘 방식이다.

## 흐름

1. **작업**: 구현 에이전트는 `main`에서 작업 브랜치(예: `test/test03-2`)를 만들어 커밋하고 push한다.
2. **제안**: 같은 브랜치에 `PR/NNN-<짧은-이름>.md`를 추가한다. `NNN`은 세 자리 일련번호이며 이전 번호에 이어 붙인다.
3. **검토**: 검토자는 같은 파일 아래쪽의 "검토" 절에 검토 결과를 추가해 그 브랜치에 커밋한다.
4. **수정**: 구현 에이전트는 수정 커밋을 push하고, 파일의 "수정 내역" 절에 반영 내용을 추가한다.
5. **병합**: 병합 승인이 나면 검토자가 브랜치를 `main`에 병합하고, 파일 상단의 상태를 `병합됨`으로 바꾼다.

한 PR 문서는 한 브랜치에 대응한다. 과거 PR 문서는 지우지 않고 기록으로 남긴다.

## 파일 양식

```markdown
# PR NNN: <제목>

| 항목 | 내용 |
|---|---|
| 상태 | 검토 대기 / 수정 요청 / 병합됨 / 닫힘 |
| 브랜치 | <작업 브랜치> → main |
| 기준 커밋 | <main 커밋> |
| 최신 커밋 | <브랜치 최신 커밋> |
| 관련 문서 | <작업 지시서, 결과 문서 경로> |

## 구현 요약
## 실행 방법
## 결과 요약
## 문서와 다르게 처리한 부분
## 질문

---

## 검토
### <날짜> 검토 1
<검토 결과, 수정 요청, 질문 답변>

## 수정 내역
### <날짜> <커밋>
<반영 내용>
```
