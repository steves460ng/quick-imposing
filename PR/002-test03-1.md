## 제안 내용

### 구현 요약

TASK-03-1을 최우선 기준으로 template@2와 project@1을 구현했습니다. main `afb5e31`에서 만든 `test/test03-1` 브랜치입니다.

- 시작 위치·개수·피치·셀 크기로 고정 셀 번호를 만들고, order 오름차순으로 B를 그립니다. 겹침은 경고하며 판 밖은 Form BBox로 잘라냅니다.
- 템플릿 생성 명령은 template.json과 바이트가 동일한 base.pdf 사본을 새 폴더에 저장합니다.
- B는 프로젝트 기준 상대경로로 읽고, PDF 옆에 프로젝트를 저장할 때 경로를 다시 계산합니다. 현재 템플릿을 다시 읽습니다.
- 텍스트는 마지막 스트림에 기준선 위치로 추가합니다. DeviceCMYK `0 0 0 1 k`, 글꼴 서브셋 임베드, ToUnicode를 적용합니다. 시스템 글꼴과 --font-dir를 지원합니다.
- R1~R11을 유지합니다. 특히 저장 전 카탈로그·페이지의 `/PieceInfo/Illustrator`만 제거하고 다른 앱의 PieceInfo와 원본 콘텐츠·리소스를 보존합니다. 이는 이전 결과에서 Illustrator가 카드 배치 전 편집 데이터를 열던 문제의 처리입니다. 이번 결과의 Illustrator 직접 확인은 별도로 남겨 두었습니다.
- 자동 배열과 GUI는 포함하지 않습니다. samples/input과 기존 docs는 수정하지 않았고, 이전 layout.json·실행 환경 전용 경로·압축 프리셋을 가져오지 않았습니다.

### 실행 방법

Python 3.12+, qpdf와 Poppler 실행 파일이 PATH에 필요합니다. 한글 픽스처는 Noto Sans CJK KR Regular를 사용합니다.

```sh
python -m pip install -e '.[test]'
quick-imposing create-template samples/test03-1/template-defs/T31-front-3x8.json \
  --base samples/input/base-front-blank.pdf --templates-root out/my-templates
quick-imposing build samples/test03-1/projects/T31-01.qiproj.json \
  --templates-root out/my-templates --output out/example/result.pdf
python -m pytest -q
python test03_runner.py
```

기존 출력은 덮어쓰지 않습니다. 재실행은 새 --out 경로를 지정합니다. 실행기는 템플릿 6개를 생성하고 `out/test03-1/summary.json`과 케이스별 결과를 만듭니다. out은 커밋하지 않습니다.

### 문서와 다르게 처리한 부분

핵심 테스트 동작과 수치는 문서대로 구현했습니다. C4의 참조는 원본을 비트맵으로 만든 뒤 회전하는 대신, 원본 페이지와 독립 행렬·판 좌표계 클립으로 만든 참조 PDF를 렌더링합니다. 소수점 좌표의 이중 샘플링 오차를 피하기 위한 검증 방식이며 엔진과 공유하지 않습니다.

픽스처의 원본 베이스 경로를 담기 위해 외부 `{source_base, template}` 래퍼를 사용했습니다. 저장되는 template.json 자체는 §2.1 형식을 따릅니다. 문서에 없는 실패 입력에는 임의 대체 없이 원인을 적어 SCHEMA_INVALID로 종료합니다. TrueType/CID-keyed CFF를 지원하며 name-keyed CFF는 지원하지 않습니다.

직접 재실행했습니다. pytest 34개 통과, 실행기 10/10 PASS가 재현됐습니다. 독립 대조에서도 문제가 없었습니다(TASK-03-1 §4.3 행렬·BBox 9건, 그리기 순서, 베이스·B 콘텐츠 바이트 보존, R11, 텍스트 위치·K100, 예외 코드, 상대경로 재계산). 다만 아래 1번 결함이 있어 병합하지 않았습니다.

#### 1. (필수) 글꼴 굵기가 잘못 선택됨

- **현상**: 템플릿은 `"font": "Noto Sans CJK KR"`(Regular 의도)를 지정했지만, 결과 PDF에 임베드된 글꼴은 `GJOQXT+NotoSansCJKkr-Black`입니다(`pdffonts out/test03-1/T31-01/result.pdf`). PR 설명과 결과 문서의 "Noto Sans CJK KR Regular 사용, 확인함"은 실제와 다릅니다.
- **원인**: `imposing/fonts.py` `catalogue()`
  - `NotoSansCJK-Black.ttc`(index 1)의 이름 테이블: nameID 1 = `Noto Sans CJK KR Black`, nameID 2 = `Regular`, nameID 16 = `Noto Sans CJK KR`, nameID 17 = `Black`
  - nameID 16으로 `noto sans cjk kr`에 매칭되고, nameID 2가 `Regular`이므로 rank 0으로 판정됩니다.
  - 파일 이름순으로 Black이 Regular보다 먼저 등록되고, 같은 rank인 Regular가 나중에 와도 교체되지 않습니다.
- **영향**: Windows 시스템 글꼴에서도 같은 가족의 다른 굵기가 선택될 수 있습니다.
- **수정 요청**
  - 스타일을 판정할 때 nameID 17(typographic subfamily)이 있으면 그 값을 우선하고, 없으면 nameID 2를 씁니다.
  - nameID 1·4·6이 정확히 일치하는 글꼴을 nameID 16만 일치하는 글꼴보다 우선합니다.
  - 테스트에 임베드된 글꼴의 PostScript 이름(BaseFont에서 서브셋 접두사를 뗀 이름)이 기대한 글꼴과 같은지 확인하는 항목을 추가합니다.
  - 결과 문서의 글꼴 확인 내용을 정정합니다.

#### 2. 질문에 대한 답

1. **`{source_base, template}` 래퍼**: 테스트 픽스처 전용으로 유지합니다. `template@2`의 일부가 아니며, 저장되는 `template.json`에는 원본 경로가 남지 않아야 합니다. README 또는 결과 문서에 "테스트 실행기 전용"이라고 명시해 주세요.
2. **T31-09 기준**: T31-01에 `extra`를 더한 구성이 맞습니다. 다만 결과 PDF의 페이지 콘텐츠가 T31-01과 같다는 대조를 추가해 주세요(무시가 실제로 결과에 영향이 없는지 확인).
3. **기타 입력 오류**: 별도 오류 코드는 두지 않습니다. 지금처럼 `SCHEMA_INVALID`와 사유 텍스트로 처리합니다.
4. **피치**: 0은 허용, 음수는 `SCHEMA_INVALID`입니다. 피치 0으로 셀이 겹치면 기존 규칙대로 `CELL_OVERLAP` 경고만 내고 진행합니다. 음수 오류와 피치 0 경고 케이스를 테스트에 추가해 주세요.
5. **완전히 판 밖인 셀**: `drawn=false`, `bbox=null`로 확정합니다. 경고는 내지 않습니다. 셀 배정은 프로젝트에 그대로 유지되어야 합니다(템플릿 수정 후 다시 열면 그려질 수 있도록). 이 동작을 테스트로 확인해 주세요.
