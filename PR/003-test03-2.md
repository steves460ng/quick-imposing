## 구현 요약

`autofill` 명령이 기존 프로젝트 또는 템플릿 이름을 받아 새 project@1 파일과 JSON 리포트를 저장한다. 숫자·대소문자 무시 파일 이름 정렬 후 현재 템플릿의 forward/reverse 순서에서 지정한 시작 셀부터 배정한다. 새 order는 기존 최댓값 다음부터 증가한다.

점유 셀이나 채움 순서 끝에 닿으면 부분 결과를 저장하고 `AUTOFILL_BLOCKED`에 사유·막힌 셀·정렬된 미배정 파일 목록을 남긴다. 입력 오류는 사유가 있는 오류 리포트만 저장한다. 기존 배정과 텍스트를 보존하고, B 상대경로를 출력 프로젝트 위치에 맞춰 다시 계산한다. 기존 출력 프로젝트와 리포트는 덮어쓰지 않는다.

PDF는 기존 3-1차 `build` 명령으로 생성한다. 테스트용 템플릿 3종, 입력 프로젝트 2개, T32-01~11 배정·PDF 기대값, 실행기와 pytest를 추가했다. 기대값은 테스트 코드만 읽는다. `{source_base, template}` 래퍼는 테스트 실행기 전용이며 저장된 template@2에는 원본 경로가 남지 않는다.

## 실행 방법

README에 따라 의존성과 qpdf·Poppler·Noto Sans CJK KR Regular를 준비한다.

```sh
python -m pytest -q
python test32_runner.py
# 재실행 시 새 출력 폴더
python test32_runner.py --out out/test03-2-review
```

기본 실행기로 템플릿을 준비한 뒤:

```sh
quick-imposing autofill --template T32-fwd-3x3 \
  --templates-root out/test03-2/templates --start-cell 1 \
  --files samples/test03-2/data/c-10.pdf samples/test03-2/data/c-2.pdf \
  --output out/review/filled.qiproj.json \
  --report out/review/autofill-report.json
quick-imposing build out/review/filled.qiproj.json \
  --templates-root out/test03-2/templates --output out/review/pdf/result.pdf
```

기존 프로젝트를 편집하려면 `--template` 대신 `--project <입력 프로젝트>`를 지정한다. CLI의 새 B 상대경로는 실행 폴더 기준이다. 상세 옵션과 리포트 경로 규칙은 README에 기록했다.

### 2026-11-11 검토 2 — 수정 요청 (개선 권고를 이번 PR에 포함)

사용자 결정으로 검토 1의 개선 권고를 이번 PR에서 처리한 뒤 병합한다.

**요청: 생성 리포트 파일 이름을 PDF 이름에 맞춤**

- 현재 `imposing/engine.py`는 생성 리포트를 출력 PDF 옆에 고정 이름 `report.json`으로 쓴다. 그래서 같은 폴더에 두 번째 PDF를 만들면 덮어쓰기 거부로 실패한다.
- 변경: 리포트 이름을 `<PDF 이름에서 확장자를 뺀 부분>.report.json`으로 한다. 예: `front-01.pdf` → `front-01.report.json`
  - 프로젝트(`<이름>.qiproj.json`)와 미리보기(`<이름>.png`)는 이미 PDF 이름을 따르므로 바꾸지 않는다.
- 덮어쓰기 규칙은 유지한다. 같은 이름의 PDF, 프로젝트, 미리보기, 리포트 중 하나라도 이미 있으면 거부한다. 오류 케이스처럼 PDF를 만들지 않는 경우에도 리포트 이름은 같은 규칙을 따른다.
- 실행기·테스트·README에서 `report.json`을 참조하는 부분을 새 이름에 맞춘다.
  - 기존 문서(`docs/TASK-03-1.md`, `docs/TEST-03-1-RESULTS.md` 등)에 나오는 `report.json`은 "생성 리포트"를 뜻하는 것으로 보고 수정하지 않는다. 새 이름 규칙은 README와 이 PR 문서에 기록한다.
- 테스트 추가
  1. 같은 폴더에 이름이 다른 PDF 두 개(예: `a.pdf`, `b.pdf`)를 연속으로 생성 → 둘 다 성공하고 파일 8개(PDF·프로젝트·미리보기·리포트 × 2)가 생긴다.
  2. 같은 이름으로 다시 생성 → 거부되고 기존 파일 4개는 바이트 단위로 그대로다.
