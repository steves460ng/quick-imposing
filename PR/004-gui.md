## 구현 요약

**결정** (`docs/UI-DESIGN.md`): 핸드오프 미결 1·2·3·6·7을 정했다. 화면 구성, 텍스트 이름표(`id`를 이름표로 사용), 겹침 경고 위치, Windows 검증 방법(GitHub Actions), 배포 형태(압축 해제형 폴더, 런타임 · qpdf · Poppler 포함).

**GUI** (`imposing/gui/`, PySide6)
- 작업 프로그램 `QuickImposing`: 템플릿 선택 → 텍스트 입력 → 셀에 B 넣기(불러오기 · 끌어다 놓기 · 자동 배열 · 교체 · 비우기) → PDF 저장. 프로젝트 다시 열기.
- 템플릿 편집기 `QuickImposingEditor`: 템플릿 생성 · 수정 · 복제 · 삭제, 셀 배열과 텍스트 항목 입력, 실시간 미리보기, 겹침 · 판 이탈 안내.
- 미리보기는 베이스 위에 B를 회전 · 클리핑 · 넣은 순서대로 그린다. 최종 PDF는 항상 기존 엔진(`generate`)이 만든다. 미리보기 코드는 PDF 생성 경로와 분리되어 있다(R10).

**화면 없는 계층** (테스트 대상)
- `imposing/store.py`: 템플릿 폴더 목록 · 읽기 · 생성 · 수정(원자적 교체) · 삭제, 임베드 가능한 글꼴 목록.
- `imposing/session.py`: 작업 편집 상태. 한 파일 배정(교체 시 order 유지), 자동 배열, 프로젝트 열기, 저장(엔진 호출, 덮어쓰기 거부, 실패 시 잔여 파일 없음).

**엔진 변경** (배치 결과에는 영향 없음)
- `autofill.plan_fill` 분리: 명령행 자동 배열과 GUI가 같은 채움 · 막힘 로직을 쓴다.
- `pdf.invoke`: Windows에서 외부 도구 콘솔 창 숨김. `pdf.check` · `render`: 임시 폴더 안에서 파일 이름만 넘겨 한글 경로가 도구 명령행에 들어가지 않게 했다. `render_bytes`: 미리보기용(경로 없이 stdin/stdout).
- **`qpdf --check` 경고 허용**: 아래 "발견한 결함 1".

**배포 · 검증**
- `packaging/quick-imposing.spec`: PyInstaller로 두 프로그램을 한 폴더에 빌드.
- `.github/workflows/windows.yml`: Windows에서 pytest, 3-1차 · 3-2차 실행기, 맑은 고딕 + 한글 경로 빌드, GUI 시작 점검, 배포 폴더 빌드와 시작 점검, 아티팩트 업로드.

## 문서와 다르게 처리한 부분

- **역할**: 구현을 Codex가 아니라 검토자가 했다(사용자 위임).
- **문서 반영 위치**: 문서는 main에 직접 커밋하는 것이 기존 방식이지만, 이번에는 구현과 함께 작업 브랜치에만 올렸다. 이 세션은 작업 브랜치에만 push할 수 있다.
- **V1**: "`qpdf --check` 오류 없음"을 "오류 없음, 경고는 기록"으로 구체화했다(결함 1).
- **없는 B 파일**: 요구사항은 "안내 없이 빈칸"이다. 대화상자는 띄우지 않되, 미리보기의 해당 셀에 빗금과 "파일 없음"을 표시한다. 배정이 유지되어 자동 배열이 그 셀에서 막히므로 작업자가 이유를 볼 수 있어야 한다고 판단했다.
- **실패한 저장의 리포트**: 명령행은 오류 리포트(`<이름>.report.json`)를 남기지만, GUI는 사유를 화면에 보여주고 리포트를 지운다. 같은 이름으로 다시 저장할 수 있게 하기 위해서다.
- **GitHub Actions 도입**: 저장소에 없던 CI를 추가했다. 작업 브랜치(`ccr-**`, `release/**`) push와 수동 실행에서만 돈다.

### 2026-11-13 미리보기 쏠림 수정 (0.4.2)

사용자 보고: 템플릿 편집기에서 텍스트 항목의 X를 키우면 미리보기의 판이 왼쪽으로 쏠린다.

- 원인: 미리보기 영역 계산(`SheetItem.boundingRect`)이 텍스트 항목마다 폭 120 mm를 어림값으로 더했고, 이 영역이 화면 맞춤과 `sceneRect`의 기준이었다. `X − 5 + 120 > 305`, 즉 X가 190 mm를 넘으면 판 밖 빈 영역까지 가운데 맞춤에 들어갔다. 스크롤 문제는 아니었다.
- 재현(미리보기 폭 520 px): X 35~190은 좌우 여백 25/25 px, X=200은 17/33, X=235는 10/75, X=280은 9/124.
- 수정: 화면 맞춤 기준(`fit_rect`)을 판 + 셀 + 여백으로 고정하고 텍스트 항목을 뺐다. 판 밖으로 나가는 셀은 계속 포함한다. 수정 후 X 35~280 모두 25/25 px.
- 테스트: `test_text_position_does_not_move_the_sheet`. 작업 프로그램도 같은 미리보기를 쓰므로 함께 고쳐진다. 엔진과 PDF 결과에는 영향이 없다.
