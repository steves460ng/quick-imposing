## 2. 파일 형식 (3-1차 확정본)

### 2.1 템플릿 정의 (`quick-imposing/template@2`)

템플릿 1개는 폴더 1개다: `<templates_root>/<name>/`
- `template.json`: 템플릿 정의
- `base.pdf`: 원본 베이스의 사본

```json
{
  "schema": "quick-imposing/template@2",
  "name": "BC-COMBI-전면",
  "base": "base.pdf",
  "cell": { "size_mm": [85, 50], "rotation_deg": -90 },
  "grid": { "origin_mm": [24, 49.5], "count": [3, 8], "pitch_mm": [86, 51] },
  "fill_direction": "forward",
  "text_fields": [
    { "id": "product", "x_mm": 35, "y_mm": 14, "font": "<글꼴 이름>", "size_pt": 9 }
  ]
}
```

| 키 | 규칙 |
|---|---|
| `name` | 폴더 이름과 같아야 한다. Windows 파일 이름에 쓸 수 없는 문자(`\ / : * ? " < > \|`)는 금지한다. 한글은 허용한다 |
| `base` | 템플릿 폴더 기준 상대경로. 항상 `base.pdf` |
| `cell.size_mm` | 셀 크기 [가로, 세로]. 회전·클리핑이 끝난 뒤 판 위에 놓이는 크기다 |
| `cell.rotation_deg` | 0, 90, -90, 180 중 하나. 음수가 시계 방향이다 (SPEC §4.3) |
| `grid.origin_mm` | 1번 셀의 좌상단 [x, y]. 판 좌상단이 원점이고 아래쪽이 +y다 |
| `grid.count` | [가로 개수, 세로 개수] |
| `grid.pitch_mm` | [가로 피치, 세로 피치]. 셀 시작점에서 다음 셀 시작점까지의 거리. 셀 크기보다 작아도 된다(겹침 허용) |
| `fill_direction` | `forward` 또는 `reverse`. 3-1차에서는 읽기와 형식 검사만 하고 동작에는 쓰지 않는다(3-2차) |
| `text_fields[]` | `id`(템플릿 안에서 유일), `x_mm`, `y_mm`, `font`(글꼴 이름), `size_pt` |

셀 번호는 좌상단부터 행 우선(→ 다음 ↓)으로 1부터 매긴다. 행 r, 열 c(1부터)인 셀의 좌상단 좌표는 다음과 같다.

```
x = origin_x + (c−1) × pitch_x
y = origin_y + (r−1) × pitch_y
셀 번호 = (r−1) × count_x + c
```

### 2.2 템플릿 생성 명령

템플릿 편집기가 할 "템플릿 저장"을 명령행으로 구현한다.

- 입력: 템플릿 정의 JSON과 원본 베이스 경로
- 동작: `<templates_root>/<name>/`을 만들고, 원본 베이스를 `base.pdf`로 복사한 뒤 `template.json`을 쓴다.
- 복사한 `base.pdf`의 SHA-256은 원본과 같아야 한다.

### 2.3 프로젝트 (`quick-imposing/project@1`)

```json
{
  "schema": "quick-imposing/project@1",
  "template": "BC-COMBI-전면",
  "texts": { "product": "BC-COMBI", "team": "1팀", "date": "" },
  "placements": [
    { "cell": 1, "file": "../../input/B-1.pdf", "order": 1 },
    { "cell": 2, "file": "../../input/B-2.pdf", "order": 2 }
  ]
}
```

| 키 | 규칙 |
|---|---|
| `template` | 템플릿 이름. `<templates_root>/<template>/`에서 찾는다. 템플릿은 항상 현재 저장된 템플릿을 쓴다 |
| `texts` | 텍스트 항목 `id` → 입력값. 빈 문자열은 허용하며, 아무것도 그리지 않는다. 템플릿에 있는데 값이 없는 항목도 빈 값으로 처리한다 |
| `placements[].cell` | 셀 번호 |
| `placements[].file` | B 경로. **프로젝트 파일이 있는 폴더 기준 상대경로** |
| `placements[].order` | 넣은 순서(1부터, 중복 불가). 그리는 순서는 `order` 오름차순이다(나중 것이 위) |

## 3. 처리 규칙

### 3.1 B 배치

- 기준 박스: B의 TrimBox. 없으면 MediaBox를 쓴다.
- 회전: `cell.rotation_deg`
- 정렬: 회전한 B 박스의 중심을 셀 중심에 맞춘다.
- 변환 행렬: (cx_b, cy_b)는 B 기준 박스의 중심, (CX, CY)는 셀 중심(PDF 좌표, pt)이다.

| 회전 | 행렬 `[a b c d e f]` |
|---|---|
| 0 | `[1 0 0 1  CX−cx_b  CY−cy_b]` |
| 90 | `[0 1 −1 0  CX+cy_b  CY−cx_b]` |
| −90 | `[0 −1 1 0  CX−cy_b  CY+cx_b]` |
| 180 | `[−1 0 0 −1  CX+cx_b  CY+cy_b]` |

- 클리핑: Form XObject의 `/BBox`를 **셀 영역과 판(MediaBox) 영역의 교집합**을 B 좌표계로 역변환한 사각형으로 한다.
  - 판 바깥으로 나간 부분은 이 방식으로 잘라낸다. 오류로 처리하지 않는다.
  - B가 셀보다 작으면 남는 부분은 비워 두고 그대로 진행한다.
- 벡터 비변형: SPEC §4.1 R1~R11을 그대로 따른다. 특히 다음을 지킨다.
  - 배율 변경 금지
  - 베이스 콘텐츠 스트림 불변
  - 결과를 저장하기 전에 `/PieceInfo/Illustrator` 제거

### 3.2 그리기 순서

1. 베이스(원본 콘텐츠 그대로)
2. B 셀들: `order` 오름차순
3. 텍스트 항목

### 3.3 텍스트 삽입

- 위치: `(x_mm, y_mm)`는 텍스트 첫 글자의 **왼쪽 기준선(baseline)** 위치다. 판 좌상단이 원점이다.
- 색: K100. `DeviceCMYK` `0 0 0 1 k`로 칠한다. RGB나 Gray를 쓰지 않는다.
- 글꼴: `font`는 글꼴 이름이다. 운영체제 글꼴 폴더에서 찾고, 실행할 때 `--font-dir`로 추가 폴더를 지정할 수 있게 한다.
  - 결과 PDF에 서브셋으로 임베드한다.
  - 한글이 깨지지 않아야 한다(ToUnicode 포함).
  - 윤곽선 처리는 하지 않는다.
- 글꼴을 찾지 못하면 오류 `FONT_NOT_FOUND`를 내고 PDF를 만들지 않는다.
- 텍스트는 베이스 콘텐츠를 바꾸지 않고, 새 콘텐츠 스트림으로 뒤에 추가한다.

### 3.4 저장

- 결과 PDF는 지정한 경로에 저장한다.
- 같은 폴더에 같은 이름의 프로젝트 파일(`<이름>.qiproj.json`)도 저장한다.
- 저장하는 프로젝트의 `placements[].file`은 **새 프로젝트 파일 위치 기준** 상대경로로 다시 계산한다.

### 3.5 예외 처리

| 상황 | 동작 | 코드 |
|---|---|---|
| 프로젝트의 셀 번호가 템플릿에 없음 | 오류, PDF를 만들지 않음 | `CELL_NOT_IN_TEMPLATE` |
| 템플릿을 찾을 수 없음 | 오류 | `TEMPLATE_NOT_FOUND` |
| `schema` 불일치, 필수 키 누락, 허용되지 않은 값 | 오류 | `SCHEMA_INVALID` |
| 텍스트 글꼴을 찾을 수 없음 | 오류 | `FONT_NOT_FOUND` |
| `order` 중복, 한 셀에 배정 2개 이상 | 오류 | `SCHEMA_INVALID` |
| 셀끼리 겹침 | 경고 후 진행 | `CELL_OVERLAP` (경고) |
| 셀이 판 바깥으로 나감 | 잘라내고 진행. 경고 없음 | — |
| 셀이 마크 영역에 걸침 | 그대로 진행. 경고 없음, 검사하지 않음 | — |
| B 크기가 셀과 다름 | 그대로 진행. 경고 없음 | — |
| B 파일이 없음 | 해당 셀을 빈칸으로 두고 진행. 사용자 안내는 없음. `report.json`에는 정보로만 기록 | `B_FILE_MISSING` (정보) |
| 프로젝트의 `texts`에 템플릿에 없는 `id`가 있음 | 무시하고 진행. `report.json`에 정보로 기록 | `TEXT_FIELD_UNKNOWN` (정보) |

## 5. 검증 항목

| ID | 검증 | 기준 |
|---|---|---|
| C1 | SPEC §9 구조 검증 V1~V12, V17 | 통과. V3은 "베이스 폰트 + 삽입 텍스트 폰트만 존재"로 읽는다 |

| C5 | 베이스 보존 | 셀 영역과 텍스트 영역(+여유 1mm)을 가리고 빈 베이스와 렌더링 비교 → 픽셀 차이 0 |

| C7 | 텍스트 | 위치(기준선 시작점) ±0.1mm. 색 연산자는 `0 0 0 1 k`만 사용. 폰트는 임베드·서브셋. `pdftotext`로 입력값과 같은 문자열 추출. 빈 값은 텍스트 객체 없음 |
| C8 | 템플릿 생성 | `out/.../templates/<name>/base.pdf`의 SHA-256 = 원본 빈 베이스 |
| C9 | 입력 보존 | `samples/input/`의 모든 PDF SHA-256 불변 (SPEC §10 값) |
| C10 | 오류·경고 코드 | §3.5 표대로 `report.json`에 기록. 오류 케이스는 PDF 없음 |

## 6. 작업 방식

- `main`에서 `test/test03-1` 브랜치를 만들어 작업하고 PR을 연다.
- 브랜치 `test/test02-templates`(PR #1, 닫힘)의 코드를 참고하거나 재사용해도 된다. 다만 다음은 가져오지 않는다.
  - 최상위 `layout.json`
  - `/workspace/...` 같은 실행 환경 전용 경로
  - 한 줄로 압축된 프리셋 JSON
- 다음 파일은 수정하지 않는다.
  - `samples/input/`
  - 기존 문서(`docs/SPEC.md`, `docs/TEMPLATE-REQUIREMENTS.md`, `docs/TEST-02.md`, `docs/HANDOFF-*.md`, 이 문서)
- 이 문서와 기준 문서가 모순되거나 모호하면 임의로 정하지 않는다. PR 설명의 "질문" 항목에 남긴다.
- `out/`은 커밋하지 않는다.
