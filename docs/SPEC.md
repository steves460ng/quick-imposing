## 1. 목적

베이스 PDF(A) 위에 카드 PDF(B) 여러 개를 **템플릿**의 셀 배열대로 배치해서 1페이지짜리 PDF 하나로 만든다. 결과 PDF는 인쇄용 판(하리꼬미)으로 사용한다.

이때 **A와 B의 벡터 특성(패스, 텍스트·폰트, 이미지, 색 공간, 투명도, 오버프린트, 레이어)을 변형하지 않는 것**이 핵심 요구사항이다.

판 구조(베이스, 셀 배열, 카드 회전, 텍스트 항목)는 템플릿으로 정의하고, 어느 셀에 어떤 B를 넣었는지는 프로젝트로 저장한다. 셀 크기, 셀 개수, 배열 위치는 템플릿마다 다르며 코드에 고정하지 않는다.

이 문서는 배치 엔진의 규칙(비변형 원칙, 회전·클리핑, 변환 행렬, 검증 항목)을 정한다. 사용자 요구사항과 프로그램 구성은 `docs/TEMPLATE-REQUIREMENTS.md`, 파일 형식의 세부는 `docs/TASK-03-1.md` §2를 따른다.

## 2. 범위

**포함**
- 템플릿의 셀 배열에 따라 B를 회전하고 셀 크기로 클리핑해서 배치
- 데이터를 넣은 순서(`order`)대로 겹쳐 그리기, 판 바깥 부분 잘라내기
- 텍스트 항목 값을 K100으로 삽입
- 결과 PDF, 프로젝트, 미리보기, 생성 리포트 저장
- 자동 배열(프로젝트 편집)

**제외**
- 카드별 재단선(크롭 마크) 추가
- PDF/X 규격 변환, 색 변환, 투명도 평탄화
- B에 도련을 더하거나 크기를 보정하는 처리 (§4.2)
- GUI 화면 구성. 프로그램 구성은 `docs/TEMPLATE-REQUIREMENTS.md` §4에서 다룬다

## 3. 입력 파일 실측 결과

### 4.2 B 가공 규칙 (회전 → 중심 맞춤 → 클리핑)

1. **기준 박스**: B의 TrimBox를 기준으로 한다. TrimBox가 없으면 MediaBox를 사용한다.
2. **회전**: 템플릿의 `cell.rotation_deg`(0, 90, −90, 180 중 하나)만큼 회전한다. 음수가 시계 방향이다.
   - 예: −90°이면 세로형 B가 가로형이 되고, **B의 위쪽이 판의 오른쪽을 향한다**.
3. **정렬**: 회전한 B 기준 박스의 **중심을 셀 중심에 맞춘다**.
4. **클리핑**: 보이는 영역은 **셀 영역과 판(MediaBox) 영역의 교집합**이다.
   - 객체를 지우거나 패스를 잘라내지 않는다. Form XObject의 `/BBox`로 가린다(§4.3). 원본 객체는 그대로 남는다.
   - 셀이 판 바깥으로 나가면 판 바깥 부분은 이 방식으로 잘라낸다. 오류로 처리하지 않는다.
5. **크기 차이**: B가 셀보다 크면 셀 바깥 부분이 가려지고, 작으면 남는 부분이 비어 있다. 어느 경우도 경고 없이 진행한다. 판단은 작업자 몫이다.
6. **NC 재단 여유**: B는 이후 NC 재단에 필요한 여유 수치까지 고려해 디자인되어 있다. 따라서 이 도구는 셀 크기 클리핑 외에 도련을 더하거나 크기를 보정하지 않는다. NC 재단 경로 생성은 이 명세의 범위가 아니다.

### 4.3 배치 변환 행렬과 `/BBox`

(cx_b, cy_b)는 B 기준 박스의 중심(B 좌표계, pt)이고, (CX, CY)는 셀 중심(PDF 좌표계, pt)이다.

| 회전 | 행렬 `[a b c d e f]` |
|---|---|
| 0 | `[1 0 0 1  CX−cx_b  CY−cy_b]` |
| 90 | `[0 1 −1 0  CX+cy_b  CY−cx_b]` |
| −90 | `[0 −1 1 0  CX−cy_b  CY+cx_b]` |
| 180 | `[−1 0 0 −1  CX+cx_b  CY+cy_b]` |

- `/BBox`는 셀 영역과 판 영역의 교집합을 위 행렬의 역변환으로 B 좌표계로 옮긴 사각형이다.
- 셀이 판 바깥에 완전히 있으면(교집합이 비면) 그리지 않는다. 배정은 프로젝트에 그대로 유지하며, 리포트에는 `drawn: false`, `bbox: null`로 기록한다.
- 샘플 B(TrimBox `[0 0 147.36 246.72]`)를 85×50mm 셀에 −90°로 넣으면 `/BBox`는 `[2.814 2.888 144.546 243.832]`다. 회전 후 좌우 각 1.0187mm, 상하 각 0.9927mm가 가려진다.

> v0.5까지의 −90° 전용 식(슬롯 좌하단 기준)은 재단 영역이 B 중심 기준이고 크기가 셀과 같으므로, 위 −90° 식과 같은 행렬을 낸다. 예: 시작 (24, 49.5), 피치 86×51의 1번 셀은 두 식 모두 `0 -1 1 0 65.144 1296.829`다(TASK-03-1 §4.3 T31-01 셀 1).

## 5. 좌표계와 단위

- 1 mm = 72 / 25.4 pt ≈ 2.834646 pt
- 템플릿, 프로젝트, 리포트에서는 **mm, 판 좌상단 원점, 아래쪽이 +y**(일러스트레이터·쿽 방식)를 사용한다.
- PDF 내부 계산은 **pt, 좌하단 원점**을 사용한다. 변환식: `y_pdf = 판높이 − y_top − 셀높이` (셀 좌하단 기준)
- 좌표는 소수점 셋째 자리(pt)까지 유지한다. 중간 계산에서 반올림하지 않는다.

## 6. 템플릿과 프로젝트

사용자 요구사항은 `docs/TEMPLATE-REQUIREMENTS.md` §5~§7, 파일 형식(`quick-imposing/template@2`, `quick-imposing/project@1`)의 키와 검사 규칙은 `docs/TASK-03-1.md` §2를 따른다. 이 절은 배치 엔진이 지켜야 할 규칙만 요약한다.

### 6.1 템플릿

- 템플릿 1개 = 폴더 1개다. 폴더에는 `template.json`과 원본 베이스를 바이트 그대로 복사한 `base.pdf`가 있다.
- 셀 배열은 1번 셀 좌상단(`grid.origin_mm`), 가로·세로 개수(`grid.count`), 가로·세로 피치(`grid.pitch_mm`), 셀 크기(`cell.size_mm`)로 만든다.
  - 피치는 셀 시작점에서 다음 셀 시작점까지의 거리다. 0은 허용하고 음수는 오류(`SCHEMA_INVALID`)다.
  - 피치가 셀 크기보다 작아 셀이 겹쳐도 허용한다(경고, §6.4).
  - 셀은 개별로 옮기거나 지우지 않는다.
- 셀 번호는 좌상단부터 행 우선(→ 다음 ↓)으로 1부터 매기며, 채움 방향과 관계없이 바뀌지 않는다. 행 r, 열 c(1부터)인 셀의 좌상단은 다음과 같다.

```
x = origin_x + (c−1) × pitch_x
y = origin_y + (r−1) × pitch_y
셀 번호 = (r−1) × count_x + c
```

- 회전(`cell.rotation_deg`)과 채움 방향(`fill_direction`: `forward`/`reverse`)은 템플릿마다 하나다. 작업할 때 바꾸지 않는다.
- 텍스트 항목(`text_fields`)은 위치(mm), 글꼴, 크기만 정의한다.

### 6.2 프로젝트

- 프로젝트는 템플릿 이름, 텍스트 입력값, 셀별 배정(`cell`, `file`, `order`)을 담는다.
- B 경로는 **프로젝트 파일이 있는 폴더 기준 상대경로**다. 다른 위치에 저장할 때는 새 위치 기준으로 다시 계산한다.
- 다시 열 때는 항상 **현재 저장된 템플릿**을 기준으로 읽는다.

### 6.3 그리기 순서와 텍스트

1. 베이스 (원본 콘텐츠 그대로)
2. B 셀들: `order` 오름차순. 나중에 넣은 것이 위에 그려진다
3. 텍스트 항목

텍스트 항목은 다음 규칙으로 넣는다.
- 위치는 첫 글자의 왼쪽 기준선이다.
- 색은 K100(`DeviceCMYK` `0 0 0 1 k`)이다.
- 글꼴은 서브셋으로 임베드하고 ToUnicode를 포함한다. 윤곽선 처리는 하지 않는다.
- 빈 값은 그리지 않는다.

### 6.4 예외 처리

배치 내용 때문에 작업을 막는 경우는 현재 템플릿에 없는 셀을 참조할 때뿐이다. 겹침, 크기 차이, 마크 걸침, 판 이탈은 작업자의 판단으로 보고 진행한다. 아래 표의 나머지 오류는 템플릿·글꼴을 찾지 못했거나 입력 형식이 잘못된 경우다. 그 밖의 입력 오류는 별도 코드 없이 `SCHEMA_INVALID`와 사유 텍스트로 기록한다.

| 상황 | 동작 | 코드 |
|---|---|---|
| 프로젝트의 셀 번호가 현재 템플릿에 없음 | 오류, PDF를 만들지 않음 | `CELL_NOT_IN_TEMPLATE` |
| 템플릿을 찾을 수 없음 | 오류 | `TEMPLATE_NOT_FOUND` |
| 텍스트 글꼴을 찾을 수 없음 | 오류 | `FONT_NOT_FOUND` |
| 텍스트에 글꼴에 없는 글자가 있음 | 오류. 빠진 글자를 `missing`에 기록 | `FONT_GLYPH_MISSING` |
| 글꼴 라이선스가 임베드를 금지함(`OS/2 fsType` 제한) | 오류 | `FONT_EMBED_FORBIDDEN` |
| 지원하지 않는 글꼴 형식(이름 기반 CFF) | 오류 | `FONT_UNSUPPORTED` |
| 형식 오류, 필수 키 누락, 허용되지 않은 값, `order` 중복, 한 셀에 배정 2개 이상, 음수 피치, 열 수 없거나 1페이지가 아닌 PDF | 오류 | `SCHEMA_INVALID` + 사유 |
| 생성 후 자체 검사 실패 (`qpdf --check` 오류(종료 코드 2), 입력 파일 해시 변경) | 오류 | `PDF_VALIDATION_FAILED`, `INPUT_CHANGED` |
| 셀끼리 겹침 | 경고 후 진행 | `CELL_OVERLAP` (경고) |
| B 크기가 셀과 다름 | 경고 없이 진행 | — |
| 셀이 마크 영역에 걸침 | 경고 없이 진행. 검사하지 않음 | — |
| 셀이 판 바깥으로 나감 | 잘라냄. 완전히 밖이면 그리지 않고 배정은 유지 (§4.3) | — |
| B 파일이 없음 | 해당 셀을 빈칸으로 두고 진행 | `B_FILE_MISSING` (정보) |
| 프로젝트에 템플릿에 없는 텍스트 항목이 있음 | 무시하고 진행 | `TEXT_FIELD_UNKNOWN` (정보) |

배치 허용 영역 검사는 없다. 마크와 카드 사이 거리는 템플릿을 만드는 사람이 정한다.

### 6.5 자동 배열

선택한 셀부터 여러 B를 파일 이름 숫자 정렬 순서로 넣는 **프로젝트 편집 기능**이다. PDF는 만들지 않는다. 채움 순서, 막힘 처리(`AUTOFILL_BLOCKED`), 정렬 규칙은 `docs/TEMPLATE-REQUIREMENTS.md` §6.4와 `docs/TASK-03-2.md` §2를 따른다.

## 7. 처리 방식

### 7.1 구현 방향

- 언어와 라이브러리: Python + **pikepdf**(qpdf 기반). 객체를 원본 그대로 복사할 수 있어 R1과 R2를 충족하기 쉽다.
- 절차
  1. 템플릿 폴더의 `base.pdf`를 연다. 입력 파일은 읽기 전용으로 다룬다.
  2. B 페이지를 Form XObject로 변환해서 가져온다. 이때 콘텐츠와 리소스를 원본 그대로 복사한다.
  3. XObject의 `/BBox`를 §4.3의 클리핑 영역으로 설정하고, B 페이지의 `/Group`을 옮긴다.
  4. 베이스 페이지 리소스에 XObject를 등록하고, 베이스 콘텐츠 뒤에 `q <cm> cm /Xn Do Q` 스트림을 `order` 순으로 **새로 추가**한다. 기존 스트림은 수정하지 않는다.
  5. 텍스트 항목을 새 콘텐츠 스트림으로 뒤에 추가한다.
  6. OCG를 병합한다(R7).
  7. Illustrator 전용 편집 데이터를 제거한다(R11).
  8. 저장할 때 객체 스트림 재압축이나 이미지 최적화 옵션은 사용하지 않는다.

> **R11이 필요한 이유**: Illustrator로 저장한 PDF에는 Illustrator 고유 편집 데이터(`/PieceInfo/Illustrator`, `AIPDFPrivateData` 등)가 들어 있다. Illustrator는 PDF를 열 때 이 데이터가 있으면 PDF 콘텐츠 대신 이 데이터를 읽는다. 베이스에 남은 데이터는 카드 배치 **전** 상태라서, 그대로 두면 Illustrator에서는 카드가 보이지 않는다(Chrome·macOS 미리보기에서는 정상 표시). 2026-11-10 PR #1 결과물을 Illustrator에서 직접 열어 이 처리로 문제가 해결됨을 확인했다. 이 처리 때문에 결과 PDF는 Illustrator 고유 편집 구조(아트보드·레이어 편집 정보 등)를 갖지 않으며, Illustrator는 일반 PDF로 해석해서 연다.

### 7.2 주의 사항

- pikepdf의 `add_overlay`처럼 지정한 사각형에 맞춰 **자동으로 크기를 조정하는 API**는 사용하지 않는다. 사용할 경우에는 결과 행렬이 R8을 만족하는지 반드시 검증해야 한다. 변환 행렬은 §4.3 식으로 직접 지정하는 것을 권장한다.
- 모든 B와 베이스의 OCG 이름이 `레이어 1`로 같다. 이름이 아니라 **객체 참조**로 구분해야 한다.
- 같은 B 파일을 여러 셀에 배치할 때는 XObject를 하나만 만들고 재사용해도 된다.

### 7.3 실행 인터페이스와 출력

명령은 `create-template`(템플릿 생성), `build`(프로젝트로 PDF 생성), `autofill`(자동 배열)이다. 옵션과 사용법은 `docs/DEVELOPMENT.md`에 있다.

`build`는 지정한 PDF 경로 옆에 같은 이름의 파일 4개를 저장한다.

| 파일 | 내용 |
|---|---|
| `<이름>.pdf` | 결과 PDF |
| `<이름>.qiproj.json` | 프로젝트. B 경로는 이 파일 위치 기준으로 다시 계산 |
| `<이름>.png` | 미리보기 |
| `<이름>.report.json` | 생성 리포트 (§9.3) |

- 이 중 하나라도 이미 있으면 기존 파일을 바꾸지 않고 거부한다.
- 자동 배열 결과는 새 프로젝트 파일로 저장한다. 기존 프로젝트를 덮어쓰지 않는다.
- 테스트 출력 폴더 `out/`은 저장소에 커밋하지 않는다.

### 9.3 생성 리포트

`build`가 만드는 `<이름>.report.json`에는 다음 정보를 담는다. PDF를 만들지 않는 입력 오류도 같은 이름으로 기록한다.

- 실행 시각, 최종 판정(`PASS` / `FAIL`)
- 입력 파일별 SHA-256, 사용한 템플릿과 프로젝트
- 셀별 배치: 셀 번호, 파일, `order`, `cm` 행렬, `/BBox`, 그렸는지 여부(`drawn`)
- 빈 셀 목록, 삽입한 텍스트
- 오류·경고·정보 코드와 사유 (§6.4)
- Illustrator 전용 데이터 제거 위치 (R11)
- 사람 확인이 필요한 항목 (V15, V18)

자동 배열 리포트의 내용은 `docs/TASK-03-2.md` §2.6을 따른다.
