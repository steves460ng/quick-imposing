# quick-imposing 작업 명세서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.5 (Illustrator 전용 편집 데이터 제거를 필수 요구사항으로 추가) |
| 작성일 | 2026-11-10 |
| 대상 | 구현 에이전트(Codex) 및 검수자 |
| 샘플 입력 | `samples/input/base.pdf`, `samples/input/B-1.pdf` ~ `B-3.pdf` |

---

## 1. 목적

베이스 PDF(A) 위에 카드 PDF(B) 여러 개를 정해진 규격과 간격으로 배치해서 1페이지짜리 PDF 하나로 만든다.

이때 **A와 B의 벡터 특성(패스, 텍스트·폰트, 이미지, 색 공간, 투명도, 오버프린트, 레이어)을 변형하지 않는 것**이 핵심 요구사항이다. 결과 PDF는 인쇄용 판(하리꼬미)으로 사용한다.

이번 단계는 샘플 3종(B-1 ~ B-3)으로 방식과 검증 절차를 확인하는 **테스트 단계**다. 실제 운영에서는 각각 다른 B를 24개 배치한다.

기본 배치는 **3열 × 8행(24개)**이다. 다만 작업 사양에 따라 배치(열·행 수), 여백, 카드 간 거리가 달라진다. 따라서 배치 값은 코드에 고정하지 않고 **사양(프리셋) 파일**로 받는다.

## 2. 범위

**포함**
- B 각각을 −90° 회전한 뒤, 중앙 기준으로 85×50mm로 재단(클리핑)해서 배치
- 사양(프리셋)에 따른 배치: 열·행 수, 여백, 카드 간 거리, 정렬 방식, 슬롯 직접 지정
- 사양 값 검증 (판 밖으로 나가는지, 마크와 겹치는지, 카드끼리 겹치는지)
- 결과 PDF 생성과 자동 검증 리포트 생성

**제외 (이번 단계)**
- 카드별 재단선(크롭 마크) 추가
- PDF/X 규격 변환, 색 변환, 투명도 평탄화
- GUI

## 3. 입력 파일 실측 결과

샘플 파일(2차본, 2026-11-10 교체)을 실측한 값이다. 구현에서는 이 값을 하드코딩하지 말고, 매번 파일에서 직접 읽어야 한다.

> **작업 환경 전제**: 실제 작업에서는 B의 폰트를 모두 **윤곽선(아웃라인) 처리**한 뒤 넘긴다. 따라서 B에는 폰트와 텍스트 객체가 없고, 글자는 벡터 패스로만 존재한다.

## 4. 핵심 요구사항

### 4.1 비변형 원칙 (MUST)

| ID | 요구사항 |
|---|---|
| R1 | B의 페이지 콘텐츠 스트림은 **디코딩 후 바이트가 원본과 동일**해야 한다. 연산자 재작성, 좌표 반올림, 최적화 모두 금지 |
| R2 | B의 이미지, SMask, 폰트 프로그램 스트림은 **인코딩된 원본 바이트 그대로** 복사한다. 재압축이나 재인코딩 금지 |
| R3 | A의 기존 콘텐츠 스트림과 리소스는 변경하지 않는다. B는 A의 콘텐츠 **뒤에 추가로 그리는** 방식으로만 배치한다. 유일한 예외는 R11의 Illustrator 전용 편집 데이터 제거다 |
| R4 | 래스터화 금지. 결과 PDF의 이미지 목록은 A의 이미지와 B의 이미지를 합친 것과 정확히 같아야 한다 |
| R5 | 색 공간(DeviceCMYK, Separation /All, Indexed)과 오버프린트 설정은 변환하거나 제거하지 않는다 |
| R6 | B 페이지의 투명도 그룹 속성(`/S /CS /I /K`)은 Form XObject의 `/Group`으로 동일하게 옮긴다 |
| R7 | A와 B의 OCG는 모두 결과 문서의 `/OCProperties /OCGs`에 등록하고, 기본 상태는 ON이어야 한다. OCG `/Name`은 변경하지 않는다. 표시 순서(`/Order`)에서는 카드별 그룹(예: `B-1`)으로 묶어도 된다 |
| R8 | 회전, 이동, 재단(클리핑) 외에 **배율 변경은 금지**한다. 변환 행렬의 배율 성분 절댓값은 정확히 1이어야 한다 |
| R9 | 입력 파일은 수정하지 않는다. 처리 전후 SHA-256이 같아야 한다 |
| R10 | Ghostscript나 그 밖의 재해석·재렌더링 도구로 결과 PDF를 생성하거나 후처리하지 않는다. 이런 도구는 검증용 렌더링에만 사용한다 |
| R11 | **Illustrator 전용 편집 데이터 제거 (필수)**. 결과 PDF를 저장하기 전에 문서 카탈로그와 각 페이지의 `/PieceInfo` 안에 있는 `/Illustrator` 항목만 삭제한다. `/PieceInfo`가 비게 되면 `/PieceInfo` 자체도 삭제한다. 다른 프로그램의 `/PieceInfo` 항목, 콘텐츠 스트림, 리소스는 건드리지 않는다. 입력 파일은 수정하지 않는다(R9). 처리 위치는 리포트에 기록한다 |

### 4.2 B 가공 규칙 (회전 → 재단)

1. **회전**: B를 **−90°(시계 방향 90°)** 회전한다. 회전 후 크기는 87.037 × 51.985 mm(가로형)이며, **B의 위쪽이 판의 오른쪽을 향한다**.
2. **재단**: 회전된 B의 **중앙을 기준으로 상하좌우를 균등하게 잘라 85 × 50 mm**로 만든다.
   - 샘플 기준 재단량: 회전 후 좌우 각 1.0187mm, 상하 각 0.9927mm
   - 회전 전 B 좌표계 기준: 좌우 각 0.9927mm(2.8139pt), 상하 각 1.0187mm(2.8876pt)
3. **재단 구현 방식**: 객체를 지우거나 패스를 잘라내는 방식이 아니라, **클리핑**(Form XObject `/BBox` 또는 클리핑 패스)으로 처리한다. 원본 객체는 그대로 남고, 85×50mm 바깥 부분만 보이지 않게 된다.
   - 샘플 B의 재단 영역(회전 전 B 좌표계, pt): `/BBox [2.8139 2.8876 144.5461 243.8324]`
4. **재단 기준 박스**: B의 TrimBox를 기준으로 중앙을 계산한다. TrimBox가 없으면 MediaBox를 사용한다.
5. **오류 처리**: 회전 전 B가 50 × 85mm보다 작으면 해당 파일은 처리하지 않고 오류를 보고한다.
6. **NC 재단 여유**: B는 이후 NC 재단에 필요한 여유 수치까지 고려해 디자인되어 있다. 따라서 이 도구는 85 × 50mm 재단(클리핑) 외에 도련을 더하거나 크기를 보정하지 않는다. NC 재단 경로 생성은 이 명세의 범위가 아니다.

### 4.3 배치 변환 행렬

시계 방향 90° 회전과 이동을 합친 행렬은 `[0 -1 1 0 e f]`다.

- 슬롯의 좌하단 좌표(PDF 좌표계, pt)를 (sx, sy), 재단 영역의 좌하단을 (a, b)라 하면
  - e = sx − b
  - f = sy + a + 141.732 (141.732pt = 50mm)
- 이 식을 적용하면 재단된 85×50mm 영역의 좌하단이 정확히 (sx, sy)에 놓인다.

## 5. 좌표계와 단위

- 1 mm = 72 / 25.4 pt ≈ 2.834646 pt
- 설정 파일과 리포트에서는 **mm, 좌상단 원점**(사람이 읽기 편한 기준)을 사용한다.
- PDF 내부 계산은 **pt, 좌하단 원점**을 사용한다. 변환식: `y_pdf = 페이지높이 − y_top − 카드높이`
- 좌표는 소수점 셋째 자리(pt)까지 유지한다. 중간 계산에서 반올림하지 않는다.

## 6. 레이아웃과 사양(프리셋)

### 6.1 기본 원칙

- 배치는 **사양(프리셋) 파일 하나**로 정의한다. 사양이 바뀌면 프리셋 파일만 바꾸거나 추가하며, 코드는 수정하지 않는다.
- 프리셋 하나에 다음 값이 모두 들어간다: 카드 크기, 회전, 재단 기준, 열·행 수, 카드 간 거리(가로·세로 별도), 여백 또는 정렬 방식, 배치 허용 영역.
- 불규칙한 배치가 필요한 사양에 대비해, 격자 계산 대신 **슬롯 좌표를 직접 나열**하는 방식도 지원한다.
- 기본 프리셋은 `default-3x8`이다.

### 6.2 프리셋 항목

| 키 | 의미 | 기본값 (`default-3x8`) |
|---|---|---|
| `name` | 프리셋 이름 | `"default-3x8"` |
| `card_size_mm` | 재단 후 최종 크기 [가로, 세로] | [85, 50] |
| `rotation_deg` | B 회전 각도 (시계 방향을 음수로 표기, 0/±90/180만 허용) | -90 |
| `crop_anchor` | 재단 기준 | `"center"` |
| `grid` | [열, 행] | [3, 8] |
| `gap_mm` | 카드 간 거리 [가로, 세로]. 0 이상, 실무 범위는 보통 0~1mm | [1, 1] |
| `align` | 그리드 위치 결정 방식 (아래 표 참조) | `"sheet-center"` |
| `margin_mm` | `align`이 `"margin"`일 때만 사용. 판 좌상단에서 그리드 좌상단까지의 거리 [왼쪽, 위] | — |
| `slots_mm` | 슬롯 좌상단 좌표 목록 [[x, y], …]. 지정하면 `grid`·`gap_mm`·`align`은 무시 | — |
| `safe_area_mm` | 배치 허용 영역 [x1, y1, x2, y2] (좌상단 원점) | [15, 33, 290, 458] |
| `slot_order` | 슬롯 번호 순서 | `"row-major"` (좌상단부터 → 다음 ↓) |

**`align` 방식**

| 값 | 그리드 위치 |
|---|---|
| `sheet-center` | 판 전체의 중앙에 그리드 중앙을 맞춤 (기본) |
| `safe-area-center` | 배치 허용 영역의 중앙에 그리드 중앙을 맞춤 |
| `margin` | `margin_mm` [왼쪽, 위]로 그리드 좌상단을 지정 |

**배정**: 어떤 슬롯에 어떤 B를 넣을지는 프리셋과 별도로 실행 시 지정한다(파일 목록 순서대로 슬롯 1번부터 배정). 슬롯 수보다 파일이 적으면 남는 슬롯은 비워 두고, 파일이 많으면 오류로 처리한다.

예시 (`default-3x8`):

```json
{
  "name": "default-3x8",
  "card_size_mm": [85, 50],
  "rotation_deg": -90,
  "crop_anchor": "center",
  "grid": [3, 8],
  "gap_mm": [1, 1],
  "align": "sheet-center",
  "safe_area_mm": [15, 33, 290, 458],
  "slot_order": "row-major"
}
```

### 6.3 프리셋 검증 규칙

다음 중 하나라도 해당하면 결과 PDF를 만들지 않고 오류를 보고한다.

- 슬롯이 `safe_area_mm`를 벗어남
- 슬롯끼리 겹침
- `gap_mm`가 음수이거나, `grid` 값이 1 미만
- `slots_mm`와 `grid`를 함께 지정했는데 둘의 슬롯 수가 다름 (경고만 하고 `slots_mm` 우선으로 처리해도 됨. 구현 시 둘 중 하나로 정해서 리포트에 명시)
- 회전 전 B가 재단 크기보다 작음

### 6.4 기본 프리셋(`default-3x8`) 계산 결과

| 항목 | 값 |
|---|---|
| 슬롯 수 | 24 |
| 카드 간 거리 | 가로·세로 1mm (실무에서는 보통 1mm 이하를 사용) |
| 그리드 크기 | 257 × 407 mm |
| 그리드 위치 | 왼쪽 24.0mm, 오른쪽 281.0mm, 위 49.5mm, 아래 456.5mm (좌상단 원점, 판 중앙 정렬) |

> **간격 상한 참고.** 3×8을 판 중앙에 정렬할 때 그리드 아래 끝이 허용 영역(458mm) 안에 들어오려면 세로 간격이 (410 − 400) / 7 ≈ **1.43mm 이하**여야 한다. 허용 영역 중앙 정렬(`safe-area-center`)을 쓰면 세로 간격 상한은 (425 − 400) / 7 ≈ 3.57mm다.
>
> 간격 0mm(카드끼리 맞닿음)도 허용한다. 카드 분리는 이후 NC 재단에서 처리한다(§4.2).

### 6.6 좌표 계산식 (grid 방식)

- 그리드 크기: 가로 = 열 × 카드가로 + (열−1) × 가로간격, 세로 = 행 × 카드세로 + (행−1) × 세로간격
- 그리드 좌상단 (gx, gy):
  - `safe-area-center`: gx = (x1+x2)/2 − 그리드가로/2, gy = (y1+y2)/2 − 그리드세로/2
  - `sheet-center`: gx = (판가로 − 그리드가로)/2, gy = (판세로 − 그리드세로)/2
  - `margin`: gx = margin왼쪽, gy = margin위
- 슬롯 (행 r, 열 c, 1부터 시작) 좌상단: x = gx + (c−1)(카드가로+가로간격), y = gy + (r−1)(카드세로+세로간격)
- PDF 좌표 변환과 `cm` 계산은 §4.3과 §5를 따른다.

## 7. 처리 방식

### 7.1 권장 구현 방향

- 언어와 라이브러리: Python + **pikepdf**(qpdf 기반). 객체를 원본 그대로 복사할 수 있어 R1과 R2를 충족하기 쉽다.
- 절차
  1. A를 연다. 입력 파일은 읽기 전용으로 다룬다.
  2. B 페이지를 Form XObject로 변환해서 A로 가져온다. 이때 콘텐츠와 리소스를 원본 그대로 복사한다.
  3. XObject의 `/BBox`를 재단 영역으로 설정하고, B 페이지의 `/Group`을 옮긴다.
  4. A 페이지 리소스에 XObject를 등록하고, A 콘텐츠 뒤에 `q <cm> cm /Xn Do Q` 스트림을 **새로 추가**한다. 기존 스트림은 수정하지 않는다.
  5. OCG를 병합한다(R7).
  6. Illustrator 전용 편집 데이터를 제거한다(R11).
  7. 저장할 때 객체 스트림 재압축이나 이미지 최적화 옵션은 사용하지 않는다.

> **R11이 필요한 이유**: Illustrator로 저장한 PDF에는 Illustrator 고유 편집 데이터(`/PieceInfo/Illustrator`, `AIPDFPrivateData` 등)가 들어 있다. Illustrator는 PDF를 열 때 이 데이터가 있으면 PDF 콘텐츠 대신 이 데이터를 읽는다. 베이스에 남은 데이터는 카드 배치 **전** 상태라서, 그대로 두면 Illustrator에서는 카드가 보이지 않는다(Chrome·macOS 미리보기에서는 정상 표시). 2026-11-10 PR #1 결과물을 Illustrator에서 직접 열어 이 처리로 문제가 해결됨을 확인했다. 이 처리 때문에 결과 PDF는 Illustrator 고유 편집 구조(아트보드·레이어 편집 정보 등)를 갖지 않으며, Illustrator는 일반 PDF로 해석해서 연다.

### 7.2 주의 사항

- pikepdf의 `add_overlay`처럼 지정한 사각형에 맞춰 **자동으로 크기를 조정하는 API**는 사용하지 않는다. 사용할 경우에는 결과 행렬이 R8을 만족하는지 반드시 검증해야 한다. 변환 행렬은 §4.3 식으로 직접 지정하는 것을 권장한다.
- 모든 B와 베이스의 OCG 이름이 `레이어 1`로 같다. 이름이 아니라 **객체 참조**로 구분해야 한다.
- 같은 B 파일을 여러 슬롯에 배치할 때는 XObject를 하나만 만들고 재사용해도 된다(TC2).

### 7.3 실행 인터페이스

명령행 하나로 실행하며, 다음 입력과 출력을 받는다.

- 입력: 베이스 PDF 경로, 프리셋 이름 또는 프리셋 파일 경로(생략 시 `default-3x8`), B 파일 목록(배정 순서대로)
- 선택 입력: 프리셋 값 일부를 실행 시 덮어쓰는 옵션(예: 간격, 여백). 덮어쓴 값은 리포트에 기록한다
- 출력: 결과 PDF, 검증 리포트(JSON), 미리보기 PNG
- 기본 출력 폴더는 `out/`이며, 이 폴더는 저장소에 커밋하지 않는다.
