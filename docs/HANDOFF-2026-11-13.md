## 업데이트 절차

코드나 문서가 바뀐 뒤 새 배포본을 만드는 순서다. Windows PowerShell에서 실행한다.

### 1. 버전 올리기

`pyproject.toml`의 `version`을 올려 커밋한다. zip 파일 이름과 배포 폴더의 `VERSION.txt`가 이 값을 따른다.

| 바뀐 내용 | 올리는 자리 | 예 |
|---|---|---|
| 오류 수정, 문구, 아이콘 | 셋째 자리 | 0.4.1 → 0.4.2 |
| 기능 추가, 화면 변경 | 둘째 자리 | 0.4.2 → 0.5.0 |
| 템플릿 · 프로젝트 파일 형식 변경 | 따로 판단. 기존 파일을 못 읽게 되면 안내가 필요하다 | — |

### 2. 빌드

```powershell
cd F:\DEV\quick-imposing
git pull
.\packaging\build.ps1
```

스크립트가 하는 일:

| 단계 | 내용 |
|---|---|
| 도구 준비 | `bin\qpdf`, `bin\poppler`가 없으면 GitHub Releases에서 최신본을 받는다. 있으면 건너뛴다 |
| 패키지 설치 | `.venv`가 있으면 그 Python을, 없으면 PATH의 Python을 쓴다 |
| 빌드 | `build\`와 `dist\QuickImposing\`을 지우고 새로 만든다. 빌드하는 동안 PATH를 좁힌다 |
| 폴더 완성 | `bin\`, `사용설명서.md`, `images\`, `VERSION.txt`를 넣는다 |
| 시작 점검 | 두 exe를 `--selftest`로 띄워 본다. 실패하면 원인을 출력하고 멈춘다 |
| zip | `dist\QuickImposing-<버전>.zip` |

| 옵션 | 용도 |
|---|---|
| `-Test` | 빌드 전에 pytest를 돌린다. Noto Sans CJK KR 글꼴이 설치되어 있어야 한다 |
| `-NoZip` | zip을 만들지 않는다 |
| `-ToolsOnly` | qpdf · Poppler만 준비하고 끝낸다 |

- 스크립트 실행이 막히면 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`를 한 번 실행한다.
- qpdf · Poppler를 새 버전으로 바꾸려면 `bin\qpdf`, `bin\poppler` 폴더를 지우고 스크립트를 다시 실행한다.

### 3. 배포

- `dist\QuickImposing-<버전>.zip`을 전달한다.
- 받는 PC에서는 프로그램을 닫고, 기존 `QuickImposing` 폴더를 새 폴더로 바꾼다.
- **템플릿은 프로그램 폴더 밖**(`%LOCALAPPDATA%\QuickImposing\templates`)에 있어 폴더를 바꿔도 남는다. 프로젝트와 PDF도 영향이 없다.
- 새 PC에 템플릿까지 주려면 위 템플릿 폴더의 내용을 복사해 같은 위치에 넣는다.
- 서명되지 않은 exe라 처음 실행할 때 Windows가 경고할 수 있다(`추가 정보 → 실행`).

### 4. 직접 빌드하지 않고 받기

GitHub → Actions → `windows` → 성공한 실행 → Artifacts의 `QuickImposing-windows`가 같은 스크립트로 만든 배포 폴더다(보관 14일). 워크플로는 `ccr-**` · `release/**` 브랜치 push와 수동 실행(Run workflow)에서 돈다. main push로는 돌지 않는다.

## 이번에 확인된 함정

| 증상 | 원인 | 대처 |
|---|---|---|
| "필요한 도구가 없습니다 (qpdf, pdftoppm)" | `dist\QuickImposing\bin`이 없음. 빌드 뒤 `bin` 복사를 빠뜨림 | `build.ps1`을 쓴다(복사와 점검을 함께 한다) |
| exe가 뜨지 않음, `DLL load failed while importing QtCore` | 빌드할 때 PATH의 다른 프로그램 DLL이 섞임 | `build.ps1`이 PATH를 좁혀 빌드한다. 손으로 `pyinstaller`를 부르지 않는다 |
| 아이콘이 예전 그대로 | Windows 아이콘 캐시 | `ie4uinit.exe -show`, 또는 폴더를 다른 이름으로 복사해 확인 |
| 받은 코드에 변경이 없음 | 작업 브랜치에만 있고 main에 병합되지 않음 | `git log --oneline -1`로 확인. 병합은 PR로 한다 |
| 빌드 중 `액세스가 거부되었습니다` (`dist\QuickImposing\…` 삭제 실패) | 배포 폴더의 프로그램이 실행 중이라 파일이 잠김 | 두 프로그램을 닫고 다시 실행. `build.ps1`이 빌드 전에 확인해 안내한다 |
| 명령이 파일을 못 찾음 | `dist` 등 하위 폴더에서 실행 | 저장소 폴더에서 실행한다(`build.ps1`은 어디서 불러도 저장소 기준으로 동작) |
