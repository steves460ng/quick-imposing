## 2. 기능 정의

자동 배열은 **프로젝트를 편집하는 기능**이다. 셀 하나와 B 파일 여러 개를 받아 프로젝트의 `placements`에 배정을 추가한다. PDF 생성은 기존 생성 명령(3-1차)을 그대로 쓴다.

### 2.1 입력과 출력

| 구분 | 내용 |
|---|---|
| 입력 | ① 대상 프로젝트(기존 프로젝트 파일, 또는 새로 만들 때는 템플릿 이름) ② 시작 셀 번호 ③ B 파일 목록(1개 이상, 순서 무관) ④ 템플릿 루트 |
| 출력 | ① 배정이 추가된 프로젝트 파일 ② 자동 배열 결과 리포트(JSON) |

- 명령 이름과 옵션은 구현자가 정하고 README에 적는다.
- 출력 프로젝트는 새 경로에 쓴다. 이미 있는 파일은 덮어쓰지 않는다(3-1차 저장 규칙과 같음).
- 출력 프로젝트의 `placements[].file`은 출력 프로젝트 위치 기준 상대경로다(TASK-03-1 §3.4).
- 템플릿은 항상 현재 저장된 템플릿을 읽는다. 채움 방향은 템플릿의 `fill_direction` 값이며, 실행할 때 바꾸는 옵션은 두지 않는다.

### 2.2 파일 정렬

B 파일은 **파일 이름(확장자 포함, 폴더 경로 제외)**을 기준으로 다음 규칙에 따라 오름차순 정렬한다. Windows 탐색기의 숫자 정렬과 같은 결과를 목표로 한다.

1. 이름을 숫자 구간과 숫자가 아닌 구간으로 나눈다.
2. 숫자 구간은 정수 값으로 비교한다. 예: `c-2` < `c-10`
3. 숫자가 아닌 구간은 대소문자를 구분하지 않고 비교한다.
4. 위 비교로 같으면 전체 경로 문자열로 비교해 순서를 고정한다.

이 정렬 순서가 넣는 순서다. 새 배정의 `order`는 프로젝트에 이미 있는 최대 `order` 다음 값부터 1씩 증가한다.

### 2.3 채움 순서

셀 번호는 좌상단부터 행 우선으로 매긴 고정 번호다(TASK-03-1 §2.1). 템플릿의 열 수를 `C`, 행 수를 `R`이라 하면 전체 채움 순서는 다음과 같다.

- `forward`: 각 행을 왼쪽 → 오른쪽으로. 순서는 1, 2, …, C, C+1, …
- `reverse`: 각 행을 오른쪽 → 왼쪽으로, 행은 위 → 아래로. 순서는 C, C−1, …, 1, 2C, 2C−1, …, C+1, …

3열 × 3행 예시:

```
셀 번호          forward 순서     reverse 순서
[1] [2] [3]      1 2 3            3 2 1
[4] [5] [6]      4 5 6            6 5 4
[7] [8] [9]      7 8 9            9 8 7
```

- 시작 셀이 첫 파일을 받는다.
- 다음 파일부터는 전체 채움 순서에서 시작 셀 **다음 위치**부터 이어서 넣는다. 순서상 시작 셀보다 앞에 있는 셀은 채우지 않는다.
- 판 밖에 있는 셀도 셀로 취급해 똑같이 채운다. 그리기 처리는 TASK-03-1 규칙을 따른다.

### 2.4 막힘 처리

채우는 도중 더 넣을 수 없게 되면, 그 앞까지 넣은 배정은 유지하고 멈춘다. 그리고 경고를 기록한다.

| 상황 | 동작 | 경고 |
|---|---|---|
| 다음에 채울 셀에 이미 배정이 있음 | 그 셀 앞까지 채우고 멈춤 | `AUTOFILL_BLOCKED`, `reason: "occupied"`, `blocked_cell: <셀 번호>` |
| 채움 순서의 끝에 도달했는데 파일이 남음 | 마지막 셀까지 채우고 멈춤 | `AUTOFILL_BLOCKED`, `reason: "end_of_cells"` |
| 시작 셀에 이미 배정이 있음 | 아무것도 넣지 않음 | `AUTOFILL_BLOCKED`, `reason: "occupied"`, `blocked_cell: <시작 셀>` |

- 경고에는 들어가지 못한 파일 목록(정렬 순서)을 함께 기록한다.
- 막혀도 출력 프로젝트는 저장한다. 배정이 하나도 추가되지 않았더라도 저장한다.
- 이미 있는 배정은 바꾸지 않는다. 셀, 파일, `order` 모두 그대로다.

### 2.5 오류

오류가 나면 출력 프로젝트를 쓰지 않고, 리포트에 사유를 기록한다.

| 상황 | 코드 |
|---|---|
| 시작 셀이 템플릿에 없음 | `CELL_NOT_IN_TEMPLATE` |
| 템플릿을 찾을 수 없음 | `TEMPLATE_NOT_FOUND` |
| 파일 목록이 비어 있음, 목록의 파일이 존재하지 않음, `fill_direction` 값이 잘못됨 등 그 밖의 입력 오류 | `SCHEMA_INVALID` + 사유 텍스트 |

### 2.6 리포트 내용

- 템플릿 이름, `fill_direction`, 시작 셀
- 정렬된 파일 목록
- 추가된 배정 목록(`cell`, `file`, `order`)
- 들어가지 못한 파일 목록
- 경고와 오류(코드, 사유, `reason`, `blocked_cell`)

## 5. 작업 방식

- 최신 `main`에서 `test/test03-2` 브랜치를 만들어 커밋하고 push한다. **GitHub PR은 열지 않는다.**
- 같은 브랜치에 `PR/003-test03-2.md`를 `PR/README.md` 양식으로 작성한다. 상태는 `검토 대기`로 둔다.
- 다음 파일은 수정하지 않는다.
  - `samples/input/`, `samples/test03-2/data/`
  - 기존 `docs/` 문서와 이 문서
  - `PR/README.md`, `PR/002-*.md`
- 3-1차 코드를 고쳐야 하는 결함을 발견하면, 수정하고 PR 문서에 따로 적는다.
- 문서가 모호하거나 모순되면 임의로 정하지 않는다. PR 문서의 "질문"에 남긴다.
- `out/`은 커밋하지 않는다.
