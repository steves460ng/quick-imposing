## 5. 작업 방식 · 환경 메모

### 진행 방식

- 사용자 기본 선호: 기획 · 분석 · 설계 · 문서 · 검토. **코드 작성 · 수정은 사용자가 지시할 때만** 한다. 답은 한국어로.
- 작업마다 새 브랜치(`claude/<이름>`)에서 커밋 → push → `PR/NNN-<이름>.md` 기록(다음 번호 009) → GitHub PR → 병합. 병합 직전에 기록 문서의 상태를 "병합됨(GitHub PR #N)"으로 바꾸는 커밋을 넣는다. 병합 방식은 merge commit.
- 병합은 사용자가 지시할 때만 한다. 오늘은 "Windows 통과하면 병합"처럼 조건부로 맡기는 경우가 많았다.
- 화면 · 리포트가 바뀌면 `pyproject.toml` 버전을 올린다(기능 추가는 둘째 자리, 수정은 셋째 자리).
- 사용자는 Claude 알림을 켜 두었다. 시각은 한국시간(KST, UTC+9)으로 알린다.

### Windows 검증

- `.github/workflows/windows.yml`의 push 트리거는 `ccr-**`, `release/**`뿐이다. `claude/**` 브랜치는 **수동 실행**(`workflow_dispatch`, ref = 브랜치)해야 한다. 약 6분, 러너 대기로 10~15분 늦게 시작하기도 한다.
- 결과 확인은 예약 메시지(`send_later`)로 7~10분 뒤에 한다. 로그는 `get_job_logs`(job_id, tail_lines)로 본다. 길면 파일로 저장되므로 Python으로 걸러 읽는다.
- **Windows와 Linux 패키지가 다를 수 있다.** 예: Windows용 PySide6에는 `LicenseRef-Qt-Commercial.txt`가 있고 Linux용에는 없다(PR/008 수정 내역). Linux에서 통과해도 Windows 결과를 확인한 뒤 병합한다.

### 이 세션 환경(Linux 클라우드) 준비

```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -e '.[test,gui]' ruff
apt-get install -y qpdf fonts-noto-cjk libegl1 libgl1 libxkbcommon0 libfontconfig1 libdbus-1-3   # poppler-utils는 이미 있음
export QT_QPA_PLATFORM=offscreen
python -m pytest -q                       # 136 passed
python test03_runner.py --out out/r-31    # 10/10
python test32_runner.py --out out/r-32    # 11/11 (+ 3-1차 회귀 10/10)
ruff check --select F imposing tests packaging/collect_licenses.py
```

- 이 환경에서는 GitHub의 다른 저장소(qpdf, poppler-windows 배포 파일 등)를 내려받을 수 없다(프록시 차단). Windows 배포 파일 내용은 워크플로 로그로 확인한다.
- GitHub 작업은 MCP 도구(`mcp__github__*`)로 한다. `gh` CLI는 검색에만 쓴다.
