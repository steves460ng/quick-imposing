# 인쇄 색상 기록

인쇄에서 색은 결과물의 품질을 바로 결정한다. 이 문서는 퀵 임포징 결과 PDF의 색과 관련된 원칙, 실제로 겪은 문제와 원인, 조사 방법을 모은다. 결과 PDF의 색에 영향을 줄 수 있는 변경(엔진, 카드 · 베이스 처리, PDF 저장 방식)을 하기 전에 먼저 읽는다.

규칙 자체는 [SPEC.md](SPEC.md) §4.1(R5 · R6 · R7)이 기준이다. 이 문서는 그 배경과 사례다.

## 1. 원칙

- **색 값은 바꾸지 않는다.** 카드와 베이스의 그리기 내용(content stream), 이미지, 색공간, 오버프린트는 바이트 그대로 옮긴다(SPEC R1 · R2 · R5). 엔진에는 색을 변환하거나 다시 계산하는 코드가 없다.
- **인쇄할 때 색을 해석하는 방식도 바뀌지 않게 한다.** PDF에 적힌 숫자가 같아도, 그 숫자를 감싼 구조(투명 그룹의 혼합 색공간, 출력 조건 프로파일, 오버프린트)가 다르면 인쇄기(RIP)는 다른 색을 낸다. 2026-11-20 사례가 이 경우였다.
- 유일한 예외는 R6: 카드 투명 그룹의 혼합 색공간이 CMYK가 아니면 `/DeviceCMYK`로 바꾼다(아래 §2).

## 2. 사례: 회색 글씨가 누렇게 인쇄됨 (2026-11-20, 0.9.2에서 수정)

### 증상
- 같은 원본 카드로 쿽(QuarkXPress)에서 만든 판보다 퀵 임포징 결과의 옐로우가 진하게 인쇄됨. 특히 **회색 글씨가 노랗게** 보임.
- 일러스트에서 열면 두 PDF의 색 값은 같음. 숫자는 같은데 인쇄만 다른 경우였다.

### 원인
- 원본 카드는 Ghostscript를 거쳐 만든 PDF였다. 페이지 투명 그룹의 혼합 색공간이 `/CS /DeviceRGB`였다. 이 지정은 "이 페이지의 투명도는 RGB로 섞어라"는 뜻이다.
- 회색 글씨는 그레이스케일(DeviceGray), 검정은 K 단색이었다.
- 퀵 임포징은 SPEC R6(0.9.1까지)대로 이 그룹을 카드 Form XObject에 **그대로** 옮겼다. 인쇄할 때 카드 전체가 RGB로 혼합되어 CMYK → RGB → CMYK를 거쳤다.
- 그 결과 K 단색 회색과 검정이 4색으로 바뀌었다. 같은 구조로 직접 만든 시험 카드(`tests/test_group_cs.py`와 같은 내용)의 Ghostscript CMYK 분판 결과는 아래와 같다.

  | 원래 색 | 0.9.1까지 (RGB 그룹 유지) | 0.9.2 (CMYK로 교체) |
  |---|---|---|
  | 회색 (그레이스케일 60%) | C59 M52 Y51 K20 | K 60% |
  | 검정 K 100% | C68 M68 Y65 K74 | K 100% |

- 쿽은 PDF를 내보낼 때 카드 내용을 풀어서 페이지에 직접 그리고, 카드 전체를 감싸던 그룹을 없앴다. 그래서 회색이 K 단색으로 남았다.

### 처음에 잘못 짚은 것 (다음 조사 때 참고)
- "판 페이지에 혼합 색공간 지정이 없어서"라고 추정했으나 틀렸다. 쿽 결과에도 그 지정이 없었다. 이 추정대로 판 페이지에 그룹을 넣었다면 고쳐지지 않았을 것이다.
- "출력 조건 프로파일(OutputIntent) 차이"도 의심했으나, 베이스 · 쿽 결과 · 퀵 임포징 결과 모두 프로파일이 없었다.
- 교훈: **추정하지 말고 원본 카드 · 쿽 결과 · 퀵 임포징 결과 세 파일을 같은 방법으로 비교한다.** 원본 카드를 받은 순간 원인이 드러났다.

### 수정 (GitHub PR #39, 0.9.2, SPEC v0.8.1)
- `imposing/engine.py`의 `card_group()`: 카드 투명 그룹의 `/CS`가 CMYK(`/DeviceCMYK`, 성분 4개인 `/ICCBased`)가 아니면 `/DeviceCMYK`로 바꾼다. 나머지 키(`/S /I /K`)와 원본 파일은 그대로 둔다.
- 바꾼 셀은 리포트 `info`에 `B_GROUP_CS_REPLACED`(`cell`, `file`, `original`)로 남는다. 화면에는 보이지 않는다.
- 쿽처럼 그룹을 아예 없애지 않은 이유: 격리(`/I`) 같은 카드 안 투명 효과의 범위를 지키기 위해서다(사용자 결정).
- 테스트: `tests/test_group_cs.py`. Ghostscript가 있으면 결과를 CMYK로 렌더링해 회색 · 검정이 K 판에만 있는지 확인한다.
- **사용자 실제 인쇄 확인 완료(2026-11-20)**: 회색이 쿽 판과 같게 나옴.

### 남은 위험
- 카드 PDF를 만드는 단계에서 RGB 그룹이 붙는다. 그 카드를 퀵 임포징을 거치지 않고 다른 프로그램으로 바로 인쇄하면 같은 문제가 생길 수 있다. 카드 제작 쪽 설정도 확인할 가치가 있다.

## 3. 퀵 임포징이 원본과 다르게 만드는 것

색에 영향을 줄 수 있는 차이를 모두 적는다. 새로 생기면 여기에 더한다.

| 항목 | 동작 | 색 영향 |
|---|---|---|
| 카드 투명 그룹 | Form XObject의 `/Group`으로 옮김. CMYK가 아닌 혼합 색공간은 `/DeviceCMYK`로 바꿈(R6) | 2026-11-20 사례. 0.9.2부터 CMYK |
| 판 페이지 투명 그룹 | 넣지 않음(베이스에 있으면 그대로) | 쿽 결과도 없음. 지금까지 문제 없음 |
| 출력 조건 프로파일(OutputIntent) | 베이스 것만 남음. 카드의 것은 옮기지 않음 | 카드에 프로파일이 있고 RIP이 그것을 쓰는 환경이면 차이 가능. 아직 사례 없음 |
| 레이어(OCG) | 카드 · 베이스 레이어를 모두 등록하고 **모두 켬**(R7) | 카드에 숨긴 레이어가 있으면 그 내용도 인쇄됨 |
| Illustrator 편집 데이터 | 지움(R11) | 인쇄 영향 없음. Illustrator가 "재해석"이라고 알림 |
| 텍스트 항목 | `0 0 0 1 k`(K 100%)로 그림 | 의도된 색 |

## 4. 색 문제를 조사하는 방법

### 4.1 먼저 받을 것
1. **원본 카드 PDF**: 가장 중요하다.
2. 비교 대상 결과(예: 쿽으로 만든 판 PDF)
3. 퀵 임포징 결과 PDF와 리포트(`*.report.json`)
4. 사용 중인 베이스 PDF
5. 인쇄 경로(Acrobat에서 바로 인쇄하는지, Fiery 같은 RIP을 거치는지)

### 4.2 사용자 PC에서 바로 할 수 있는 확인 (Acrobat Pro)
- `도구 → 인쇄 작업 → 출력 미리보기`를 연다. 문제가 된 지점에 커서를 올려 **C · M · Y · K 잉크 %**를 비교한다. Adobe 엔진이 투명도까지 계산한 값이 나온다.
- 같은 창의 **시뮬레이션 프로파일**로 출력 조건 프로파일을 확인하고, 분판 목록으로 별색 판을 확인한다.
- 일러스트에서 열어 보는 것만으로는 부족하다. 일러스트는 객체의 색 값만 보여 주고, 인쇄할 때의 혼합은 보여 주지 않는다.

### 4.3 구조 비교 (이 저장소 환경, pikepdf)
세 파일 각각에서 아래 항목을 본다.
- 문서: `/OutputIntents`, `/OCProperties`(꺼진 레이어 `/D /OFF`), 만든 프로그램(`/Creator`, `/Producer`)
- 페이지: `/Group`(특히 `/CS`), 리소스의 `/ColorSpace`(Separation · DeviceN · ICCBased), `/ExtGState`의 `/OP /op /OPM /BM /SMask /ca`
- XObject(재귀): 이미지 색공간과 SMask, Form의 `/Group`과 그 `/CS`
- 그리기 내용의 색 연산자: `k` · `K`(CMYK), `g` · `G`(그레이), `rg` · `RG`(RGB), `cs` · `scn`. 문제가 된 색(예: 회색) 앞뒤 문맥

### 4.4 분판 계산 (Ghostscript, 검증 전용)
```sh
gs -q -dNOPAUSE -dBATCH -dSAFER -sDEVICE=tiff32nc -r150 -sOutputFile=out.tif result.pdf
```
- 결과 TIFF의 각 픽셀이 CMYK 값이다. Pillow로 열어 문제 영역의 값이나 "K만 쓴 픽셀 / C · M · Y가 섞인 픽셀" 수를 센다.
- 레지스트레이션 마크(Separation `/All`)는 네 판 값이 같으므로 제외한다.
- 비교할 때는 구조만 바꾼 시험 PDF(예: 그룹 유지 / 제거 / CMYK로 교체)를 스크립트로 만들어 함께 렌더링한다.
- 한계: Ghostscript는 Adobe 엔진이나 실제 RIP과 다르게 처리하는 경우가 있다. 예를 들어 그레이스케일을 그대로 K로 보내서, 단순한 시험에서는 차이가 드러나지 않았다. **최종 판정은 사용자의 실제 인쇄**로 한다.
- Ghostscript는 검증용 렌더링에만 쓴다. 결과 PDF를 만들거나 고치는 데 쓰지 않는다(SPEC R10).

## 5. 변경할 때 지킬 것

- 결과 PDF의 색 구조(그룹, 색공간, 프로파일, 오버프린트, 레이어)를 바꾸는 변경은 사용자와 합의한다. SPEC과 이 문서 §3을 함께 고친다.
- 가능하면 분판 테스트(§4.4 방식, Ghostscript가 없으면 건너뜀)를 함께 넣는다.
- 고친 뒤에는 사용자에게 **실제 인쇄 확인**을 요청하고, 결과를 PR 설명과 이 문서에 적는다.
