사용 의도는 **Noto Sans CJK KR Regular**이다. 최초 문서의 “Regular 사용·확인” 기록은 Black이 함께 설치된 조합을 검증하지 못한 상태의 기록이었다. 리뷰 환경에서는 `NotoSansCJKkr-Black`이 실제로 임베드되었으므로 기존 구현이 Regular를 보장했다는 설명을 정정한다. 원인은 Black의 nameID 2가 `Regular`이고 nameID 17은 `Black`인 경우를 구별하지 못한 것이다.

수정 후에는 스타일을 nameID 17 우선(없으면 2)으로 판정하고, nameID 1·4·6의 정확한 일치를 nameID 16 별칭보다 우선한다. 실행기는 임베드·서브셋 여부뿐 아니라 결과 Type0 폰트의 **BaseFont에서 서브셋 접두사를 제외한 이름이 `NotoSansCJKkr-Regular`인지** 기대값과 직접 비교한다. Black이 먼저 검색되는 TTC 조합을 생성하는 회귀 테스트도 추가했다.

수정 후 재실행에서 텍스트가 있는 T31-01·02·08·09의 PostScript 이름은 모두 `NotoSansCJKkr-Regular`였다. `pdffonts`는 `CID Type 0C`, `Identity-H`, `emb=yes`, `sub=yes`, `uni=yes`를 보고했고 `BC-COMBI`, `1팀`, `2026.11.11` 추출도 통과했다. 시스템의 `NotoSansCJK-Regular.ttc` KR face를 사용했으며 글꼴 파일은 저장소에 복사하지 않았다.

## 리뷰에서 확정된 처리

1. **픽스처 래퍼:** `{source_base, template}`는 테스트 실행기 전용이며 template@2의 일부가 아니다. 일반 생성 CLI는 template@2 정의만 받는다. 저장된 template.json이 내부 정의와 같고 원본 경로·래퍼가 남지 않음을 검사한다.
2. **T31-09:** T31-01에 extra를 더한 구성을 사용한다. 정보 코드뿐 아니라 결과의 전체 페이지 콘텐츠 스트림과 리소스가 T31-01과 같은지 대조한다.
3. **기타 입력 오류:** 별도 오류 코드 없이 SCHEMA_INVALID와 사유를 기록한다. TrueType·CID-keyed CFF는 지원하며 name-keyed CFF는 지원하지 않는다. 글리프 누락·임베드 금지 등은 대체 처리로 숨기지 않는다.
4. **피치:** 0은 허용한다. 겹치면 CELL_OVERLAP 경고 후 그대로 그린다. 음수는 SCHEMA_INVALID로 거부하고 PDF를 만들지 않는다. 두 축의 음수와 피치 0을 회귀 테스트했다.
5. **완전히 판 밖인 셀:** 경고 없이 `drawn=false`, `bbox=null`로 기록한다. 저장 프로젝트의 셀·파일·order는 유지한다. 같은 프로젝트를 템플릿 위치 수정 후 다시 열어 실제로 그려지는 것까지 확인했다.
6. **사람 확인:** V15와 C11/V18은 병합 전 사용자가 확인한다. 자동 검사 PASS에 포함하지 않는다.

확정되지 않은 추가 질문은 없다. C4는 원본을 먼저 비트맵으로 만든 뒤 다시 회전하는 대신 원본 페이지·독립 행렬·판 좌표계 클립을 사용한 참조 PDF를 렌더링한다. 소수점 좌표의 이중 샘플링 오차를 피하면서 원본과 결과를 같은 해상도에서 비교하기 위한 검증 방식이다. 생성 엔진은 이 참조 PDF나 기대값 파일에 접근하지 않는다.
