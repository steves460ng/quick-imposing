## 사용자가 확인할 것 (우선순위 순)

1. **배포본을 Windows PC에서 실행**해 `README.md` 순서대로 템플릿 하나를 만들고 판 하나를 저장해 본다. 저장한 PDF를 Illustrator로 연다(V18).
2. `docs/UI-DESIGN.md` §6의 임의 결정 6건. 특히 같은 이름 다시 저장(지금은 덮어쓰기 금지, `이름-2` 제안)과 템플릿 폴더 위치.
3. 병합 여부. 병합한다면 `PR/004-gui.md` 상태를 `병합됨`으로 바꾼다.
4. main에 `windows` 워크플로를 둘지. 지금 트리거는 `ccr-**` · `release/**` 브랜치 push와 수동 실행이다. private 저장소라 Actions 사용량이 든다(Windows는 1회 약 6분).

## 새로 확정된 사실

- **qpdf 버전**: qpdf 12는 샘플 베이스 3종의 압축 스트림에 경고를 낸다(종료 코드 3). 베이스를 바이트 그대로 보존하므로 결과에도 같은 경고가 나온다. 경고는 통과로 보고 리포트에 기록한다(SPEC v0.6.1). 실제 운영 베이스도 같은 경로(Illustrator → Quark)로 만들면 같은 경고가 날 것으로 본다(추정).
- **Windows의 Poppler는 한글 경로 인수를 받지 못한다.** 엔진과 GUI는 이를 피하도록 되어 있다. 테스트 실행기를 한글 경로에서 돌리면 실행기의 검증 단계(`pdffonts` 등)가 실패할 수 있다. 실행기는 ASCII 경로에서 돌린다.
- **드라이브 제약**: B와 저장 위치는 같은 드라이브여야 한다(상대경로).
- **배포 빌드**: PATH에 다른 프로그램의 DLL 폴더가 있으면 배포본이 깨진다. 워크플로처럼 PATH를 좁혀 빌드한다.

## 미결 사항

1. V18과 실제 PC 확인 (위 "사용자가 확인할 것" 1).
2. `docs/UI-DESIGN.md` §6의 6건 확정.
3. Poppler(GPL) 포함 배포: 사내 사용 범위를 넘어 배포한다면 라이선스 조건 확인이 필요하다.
4. 설치 프로그램과 `.qiproj.json` 파일 연결은 만들지 않았다. 프로그램 아이콘은 2026-11-13에 추가했다(`packaging/make_icons.py`).
5. 이전 핸드오프의 브랜치 정리(`test/test02-templates`, `test/test03-1`, `test/test03-2`)와 2차 픽스처 삭제 여부는 그대로 남아 있다.
6. 임시로 추가한 진단: 배포 exe의 `--selftest`와 `packaging/_entry.py`의 DLL 점검은 빌드 검증에 계속 쓴다. 지울 필요는 없다.
