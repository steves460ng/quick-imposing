# quick-imposing 핸드오프 (2026-11-11)

## 목표와 범위

**최종 목표**
베이스 PDF 위에 카드 PDF(B)를 템플릿의 셀에 배치해 인쇄용 판(하리꼬미) PDF를 만드는 Windows용 도구를 만든다.
- 사용 대상은 그래픽 툴에 미숙한 인쇄 실무자다. 쿽(QuarkXPress)으로 하던 임포징을 대신하는 것이 목적이다.
- A(베이스)와 B의 벡터 특성(패스, 폰트, 이미지, 색 공간, 투명도, 오버프린트, 레이어)을 변형하지 않는다.
- 최종 형태는 GUI 프로그램 두 개다. 템플릿 편집기와 작업 프로그램이다.

**현재 단계**
- 배치 엔진과 명령행 도구로 기능 테스트 3-1차(셀 배열·겹침 순서·판 바깥 잘라냄·텍스트 삽입)와 3-2차(자동 배열)를 완료하고 main에 병합했다.
- GUI는 아직 착수하지 않았다.

**역할**
- 구현은 Codex(코딩 에이전트)가 맡는다.
- 이 핸드오프를 받는 쪽은 기획, 분석, 설계, 문서, 리뷰를 맡는다. 코드 작성과 수정은 사용자가 명시적으로 지시할 때만 한다.

## 제약과 선호

- **언어**: 한국어
- **저장소**: `https://github.com/steves460ng/quick-imposing`. private이다.
- **문서 반영**: 문서는 `main`에 직접 커밋한다. 커밋 작성자는 `steves460ng <steves460ng@users.noreply.github.com>`이다.
- **변경 제안·검토 방식**: GitHub Pull Request 기능은 쓰지 않는다. 규칙은 `PR/README.md`에 있다.
  1. 구현 에이전트가 작업 브랜치에 `PR/NNN-<이름>.md`를 올려 제안한다.
  2. 검토자는 같은 파일에 검토 결과를 이어 적는다.
  3. 구현 에이전트는 수정 내역을 같은 파일에 적는다.
  4. 승인되면 검토자가 브랜치를 main에 병합하고 상태를 `병합됨`으로 바꾼다.
  - 다음 번호는 004다.
- **작업 지시 방식**: 구현마다 `docs/TASK-*.md` 작업 지시서를 쓰고, 짧은 지시 프롬프트로 Codex에 전달한다.
  - 지시서에는 독립 계산한 기대값(행렬, 배정 결과 등)을 넣는다.
  - 구현 쪽 엔진은 기대값 파일을 읽지 않는다.
- **검토 방식**: 브랜치를 받아 테스트를 재실행한다. 그다음 브랜치의 픽스처·기대값을 쓰지 않고, 명령을 직접 실행해 지시서 표와 대조한다.
- **사람 확인 항목**: 방향(V15)과 Illustrator 표시(V18)는 자동 검사로 대신하지 않는다. 사용자가 직접 확인한다.

## 확정된 결정

### 배치·비변형 (`docs/SPEC.md` v0.5)

- B는 회전한 뒤 셀 크기로 클리핑해 셀 중심에 놓는다. 클리핑은 객체를 지우지 않고 Form XObject `/BBox`로 가린다.
- 변환은 회전과 이동만 쓴다. 배율은 바꾸지 않는다.
- B 콘텐츠·이미지·폰트 스트림은 원본 바이트를 유지한다. 베이스 콘텐츠는 바꾸지 않고, 그리는 명령만 뒤에 덧붙인다.
- **R11**: 결과를 저장하기 전에 `/PieceInfo/Illustrator`만 제거한다. 이 데이터가 남아 있으면 Illustrator가 배치 전 상태를 연다.
- B는 이후 NC 재단 여유까지 고려해 디자인된다. 그래서 도구는 도련 추가나 크기 보정을 하지 않는다.
- B는 폰트를 윤곽선 처리한 상태로 들어온다.
- 판 크기는 305 × 506mm(베이스 크기)이며, 이것이 인쇄 규격이다.
- 재단선은 넣지 않는다. PDF/X 변환은 범위 밖이다.

### 템플릿·프로젝트 (`docs/TEMPLATE-REQUIREMENTS.md` v0.3)

- **템플릿**: 템플릿 1개 = 폴더 1개다. 폴더에는 템플릿 정의와 원본 베이스를 복사한 `base.pdf`가 들어간다.
  - 같은 카드 크기라도 전면용과 후면용 템플릿을 따로 만든다.
  - 템플릿 폴더는 설치 폴더 안에 두며, 공유하지 않는다.
- **셀 배열**: 첫 셀 좌상단(mm), 가로·세로 개수, 가로·세로 피치, 셀 크기로 만든다.
  - 피치는 셀 시작점에서 다음 셀 시작점까지의 거리다. 0은 허용하고 음수는 오류다.
  - 셀은 개별로 옮기거나 지우지 않는다.
- **카드 가공**: 회전은 0°, 90°, −90°, 180° 중 하나다. 클리핑 크기는 셀 크기와 같다.
- **텍스트 항목**: 템플릿에는 위치(mm), 글꼴, 크기만 정의한다. 내용은 작업할 때 입력하며, 빈 값도 허용한다.
  - 색은 K100(DeviceCMYK) 고정이고, 글꼴은 서브셋으로 임베드한다.
- **프로젝트**: 프로젝트는 PDF와 같은 위치에 저장한다.
  - B는 프로젝트 파일 기준 상대경로로 참조한다.
  - 겹친 데이터는 나중에 넣은 것이 위에 그려진다(`order` 순).
  - 다시 열 때는 현재 템플릿을 기준으로 읽는다.
- **자동 배열**: 선택한 셀부터 여러 B를 파일 이름 숫자 정렬 순서로 넣는다.
  - 채움 방향은 템플릿의 `fill_direction`이다. 정방향은 행을 왼쪽에서 오른쪽으로, 역방향은 오른쪽에서 왼쪽으로 채운다.
  - 막히면 그 앞까지 채우고 경고한다. 막히는 경우는 다음 셀이 이미 차 있을 때와 셀이 끝났을 때다.
- **예외 처리**: 작업을 막는 경우는 현재 템플릿에 없는 셀을 참조할 때뿐이다.

| 상황 | 동작 |
|---|---|
| 셀 겹침 | 경고 후 진행 |
| B 크기가 셀과 다름 | 경고 없이 진행 |
| 셀이 마크 영역에 걸침 | 경고 없이 진행 |
| 셀이 판 바깥으로 나감 | 잘라냄. 완전히 밖이면 그리지 않고, 배정은 유지 |
| B 파일이 없음 | 빈칸으로 둠 |

### 파일 형식 (`docs/TASK-03-1.md` §2)

- 템플릿 정의: `quick-imposing/template@2`
- 프로젝트: `quick-imposing/project@1`
- 텍스트 위치는 첫 글자의 왼쪽 기준선이다.
- 그리는 순서는 베이스 → B 셀(`order` 순) → 텍스트다.
- 프로젝트에 템플릿에 없는 텍스트 항목이 있으면 무시하고 정보로만 기록한다.
  - 이 세 항목은 지시서의 잠정값이었다. 사용자 이의 없이 구현·병합되었다.

### 오류와 출력

- 기타 입력 오류는 별도 코드를 두지 않고 `SCHEMA_INVALID`와 사유 텍스트로 기록한다.
- PDF를 만들 때는 같은 이름의 파일 4개를 함께 저장한다: `<이름>.pdf`, `<이름>.qiproj.json`, `<이름>.png`, `<이름>.report.json`.
  - 이 중 하나라도 이미 있으면 덮어쓰지 않고 거부한다.
- 자동 배열 결과는 새 프로젝트 파일로 저장한다.

## 제안과 가정 (확정 아님)

- **SPEC의 배치 허용 영역**: SPEC에 있는 `[15, 33, 290, 458]`mm는 1차 샘플 베이스의 마크 위치로 산출한 값이다. 새 요구사항에는 허용 영역 검사가 없으므로, 이 값을 남길지 정해야 한다.
- **참고 브랜치 정리**: `test/test02-templates`(PR #1 참고본)에는 낡은 `layout.json`과 실행 환경 전용 경로가 남아 있다. 브랜치를 정리할 시점은 정하지 않았다.
- **병합된 작업 브랜치**: `test/test03-1`과 `test/test03-2`는 main에 병합되었고 원격에 남아 있다. 삭제할지는 정하지 않았다.

## 미결 사항

1. **UI 구성**: 템플릿 편집기와 작업 프로그램의 화면 구성
2. **텍스트 입력칸 이름표**: 작업 화면에 항목 이름표(예: 제품명)를 표시할지
3. **겹침 경고 위치**: 겹침 경고를 언제, 어디에 보여줄지(템플릿을 편집할 때, 작업할 때)
4. **기존 문서 개정**: SPEC과 TEST-02 본문에는 새 요구사항으로 대체된 규칙이 남아 있다. 예: `CARD_TOO_SMALL`·`SLOT_OVERLAP` 오류, `gap_mm`, 85×50 고정, 생성 리포트 이름 `report.json`. 이를 개정할지, 대체 표시만 할지 정해야 한다.
5. **SPEC 미결 항목**: 마크와 카드 사이 최소 거리. 마크 영역 겹침을 그대로 두는 현재 규칙에서는 영향이 작다.
6. **실행 환경**: Windows에서 실제로 실행해 본 적이 없다. 자동 검증은 Linux에서만 수행했다. Windows 시스템 글꼴 폴더 검색도 확인하지 않았다.
7. **배포 형태**: 설치 방식, 템플릿 설치 폴더 위치, Python 런타임을 포함할지가 정해지지 않았다.
